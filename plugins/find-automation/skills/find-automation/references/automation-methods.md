# 자동화 방법 카탈로그

후보 하나에 2~4개만 골라 제시한다. 고르는 기준은 **매번 같은 단계인가(결정적) vs 매번 판단이 필요한가**, 그리고 **누가 시작하는가(사람 / 이벤트 / 시간)** 이다.

| 신호 | 1순위 방법 |
|---|---|
| 같은 명령 묶음을 그대로 반복 (CC#, F#) | 셸 스크립트 / alias / Makefile·package.json 스크립트 |
| 같은 종류의 요청인데 매번 내용 판단 필요 (P#, T#) | 커스텀 스킬 |
| 특정 도구 사용 전후에 항상 해야 하는 일, 또는 반복되는 정정 (R#) | hook 또는 CLAUDE.md 규칙 |
| 정해진 시각·주기로 하는 일 ("매일 아침", "매주 월요일") | 스케줄 작업 |
| "계속 진행해줘"·권한 승인 반복 (1-c) | CLAUDE.md 규칙 / 권한 allowlist |
| 반복 조사·리뷰를 큰 컨텍스트 없이 맡기고 싶음 | 서브에이전트 정의 |

---

## 1. 셸 스크립트 / alias

- **맞는 경우**: 단계가 고정돼 있고 입력값 몇 개만 바뀔 때. 예: PR 생성 → checks 대기 → 머지.
- **장점**: 몇 초 만에 끝나고 토큰을 쓰지 않으며 Claude 없이도 실행된다. / **단점**: 예상 밖의 상황(충돌, 실패)을 판단하지 못한다.
- **위치**: 프로젝트 전용이면 레포의 `scripts/`, 개인용이면 `~/bin/` 또는 `~/.local/bin/` (PATH에 있는지 확인).
- **만드는 법**: `#!/usr/bin/env bash` + `set -euo pipefail`. 인자 검증, `--dry-run`, `-h` 지원. 비밀값은 환경변수나 기존 인증(gh auth, aws sso)을 쓴다.
- **테스트**: `--dry-run`으로 실행 → 잘못된 인자 → 실제 실행(부작용이 있으면 사용자 확인 후).
- Claude가 쓰게 하려면 CLAUDE.md에 "PR 머지는 `scripts/prship` 사용" 한 줄을 추가하자고 제안한다.

## 2. 커스텀 스킬 (자동 호출)

- **맞는 경우**: 같은 종류의 일이지만 매번 내용을 읽고 판단해야 할 때. 예: Confluence 문서 작성, 장애 로그 분석, 주간 보고.
- **장점**: 사용자가 이름을 몰라도 description 매칭으로 자동 호출되고, 예외 상황도 처리한다. / **단점**: 매번 모델이 수행하므로 느리고 토큰이 든다. description을 잘 써야 호출된다.
- **위치**: 개인용 `~/.claude/skills/<name>/SKILL.md`, 레포 공유용 `<repo>/.claude/skills/<name>/SKILL.md`.
- **만드는 법**: skill-creator 스킬이 있으면 그 절차를 따른다. 없으면 frontmatter의 `name`과 `description`을 쓴다. description에는 사용자가 실제로 할 법한 말과 상황을 넣는다. 본문에는 trace로 확인한 실제 단계, 고정값, 주의사항을 쓴다. 반복되는 결정적 단계는 `scripts/`에 넣는다.
- **테스트**: 트리거 문장 2~3개를 제시한다. 가능하면 `claude -p "<문장>"`으로 새 세션에서 호출되는지 확인한다.

## 3. 슬래시 커맨드 (명시 호출 전용 스킬)

- **맞는 경우**: 자동으로 끼어들면 곤란하고, 사용자가 원할 때만 실행해야 할 때. 예: 배포, 릴리스 노트, 슬랙 공유 메시지 작성.
- **장점**: 예상치 않은 자동 호출이 없고 `/이름 인자`로 빠르게 실행한다. / **단점**: 이름을 기억해야 한다.
- **만드는 법**: 스킬 frontmatter에 `disable-model-invocation: true`를 넣는다(또는 `~/.claude/commands/<name>.md`). 본문에서 `$ARGUMENTS`로 인자를 받는다.

## 4. Hook

- **맞는 경우**: "항상 X 전후에 Y" 같은 결정적 규칙, 반복해서 지적한 금지사항, 알림. 예: Edit 후 포매터 실행, `git push --force` 차단, 작업 끝나면 macOS 알림.
- **장점**: 모델의 기억에 의존하지 않고 매번 강제된다. / **단점**: 판단을 하지 못하고, 잘못 만들면 매번 방해한다.
- **이벤트**: `PreToolUse`(차단·검증, exit 2이면 차단하고 stderr를 Claude에게 전달), `PostToolUse`(포맷·린트), `UserPromptSubmit`(컨텍스트 주입), `Stop`(마무리 검사), `SessionStart`(상태 주입), `Notification`.
- **위치**: 개인용 `~/.claude/settings.json`, 레포 공유용 `.claude/settings.json`의 `hooks`. update-config 스킬이 있으면 그것으로 편집한다.
- **테스트**: 샘플 입력 JSON을 stdin으로 넣어 직접 실행한다. 예: `echo '{"tool_name":"Bash","tool_input":{"command":"git push -f"}}' | ./hook.sh; echo $?`

## 5. 스케줄 작업

- **로컬 cron / launchd + 스크립트 또는 `claude -p`**
  - 장점: 데이터가 로컬에 머물고 사내망·로컬 자격증명을 쓸 수 있다. / 단점: 맥이 꺼져 있으면 실행되지 않는다. launchd plist 관리가 번거롭다.
  - `claude -p`를 쓸 때는 `--allowedTools`로 권한을 최소화한다. 출력은 파일이나 알림으로 남긴다.
- **`/schedule` 클라우드 루틴**
  - 장점: 맥이 꺼져 있어도 돈다. / 단점: 클라우드에서 실행되므로 사내 데이터·자격증명을 다룬다면 보안 검토가 필요하고, 로컬 리소스에 접근할 수 없다. 반드시 이 점을 사용자에게 알린다.
- **`/loop`**: 열려 있는 세션 안에서 주기적으로 반복한다(배포 상태 폴링 등). 세션을 닫으면 멈춘다.

## 6. CLAUDE.md 규칙 / 메모리

- **맞는 경우**: 같은 정정을 반복할 때(R#), "계속 진행해줘"를 자주 칠 때(1-c), 매번 같은 컨텍스트를 설명할 때.
- **장점**: 한 줄이면 되고 즉시 효과가 있다. / **단점**: 강제력이 없어 모델이 놓칠 수 있다. 꼭 지켜야 하면 hook으로 만든다.
- **위치**: 전역 `~/.claude/CLAUDE.md`, 레포 `CLAUDE.md`. 규칙에는 이유를 함께 쓴다.

## 7. 권한 allowlist

- **맞는 경우**: 같은 안전한 명령을 매번 승인할 때.
- **장점**: 승인 대기가 없어진다. / **단점**: 너무 넓게 열면 위험하다. 읽기 전용 명령 위주로 연다.
- 내장 `fewer-permission-prompts` 스킬이 있으면 그것을 안내한다.

## 8. 서브에이전트 정의

- **맞는 경우**: 반복되는 조사·리뷰·검증을 메인 컨텍스트를 더럽히지 않고 맡기고 싶을 때.
- **장점**: 격리된 컨텍스트에서 도구를 제한해 실행한다. / **단점**: 결과만 돌아오므로 중간 과정을 보기 어렵다.
- **위치**: `~/.claude/agents/<name>.md` (frontmatter: name, description, tools).

## 9. 플러그인으로 묶기

- 위 여러 개(스킬 + hook + 스크립트)를 팀과 공유하려면 플러그인 하나로 묶는다(`.claude-plugin/plugin.json`, `skills/`, `hooks/hooks.json`). 개인 자동화에는 보통 과하다.
